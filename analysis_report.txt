# Integration Failures Analysis

## 1. **Database Schema vs API Endpoints**

### manage-user API:
- **Critical Failure**: Attempts to use `target_resource` column in `audit_logs` table, but schema shows only: `id, actor_id, action, entity_type, entity_id, created_at, ip_address`
- **Risk**: Foreign key constraint violation - When deleting users, it tries to delete auth user first while `public.users` has foreign key constraint to `auth.users`. Should delete from `public.users` first.
- **Missing Field**: `users` table has `organization_id` column but API doesn't handle it.

### manage-session API:
- **Missing Required Columns**: `sessions` table requires `max_participants` (defaults to 15) and `delivery_mode` with check constraint
- **Status Mismatch**: Status values in code vs schema - schema allows: `['planned', 'scheduled', 'confirmed', 'active', 'in_progress', 'completed', 'cancelled', 'audited']`
- **Audit Log Issue**: Same `target_resource` column doesn't exist

### manage-standard API:
- **Schema Mismatch**: No `target_resource` column in `audit_logs`
- **Missing Field**: `training_standards` has `details jsonb DEFAULT '{}'` column not handled

## 2. **UI Component - PurpleAdminDashboard**

### Data Fetching Logic:
- **Critical**: Uses deprecated `count: 'exact', head: true` syntax - Supabase v2 changed to `count: 'exact'`
- **Incomplete Function**: `fetchStats` function cuts off mid-line: `const { count: u24` 
- **Mixed Table References**: Uses both `session_participants` and `session_roster` tables inconsistently
- **Missing Time Filters**: Defines `last24hDate` but doesn't use it in queries
- **Role Name Mismatch**: Searches for `role: 'instructor'` but schema has `'instructor'` (correct), but also refers to 'trainers'
- **Admin Role Confusion**: Searches `role: 'ernam_admin'` but dashboard shows 'administrators'

### Mock Data Issues:
- **Integration Gap**: Uses mock data (`USERS_DATA`, `TRAINEE_ROSTER_DATA`) instead of actual database queries
- **Stats Properties Mismatch**: `getDynamicStatsCategories` expects `docs24h`, `users24h`, `certs24h` but fetchStats doesn't compute these
- **Incomplete KPI Calculations**: Functions like `getDynamicTraineeKpis` use stats that aren't fetched (e.g., `stats.trainees`, `stats.certificates`)

## 3. **Logical Errors & Data Mapping**

### Role System Inconsistency:
- Schema: `['participant', 'instructor', 'org_admin', 'ernam_admin', 'maintainer', 'developer']`
- UI references: 'trainees', 'trainers', 'administrators', 'Level 1/2'
- No direct mapping between display names and database roles

### Status Value Mismatch:
- `session_participants.attendance_status`: `['enrolled', 'attended', 'absent']`
- `session_roster.status`: `['nominated', 'approved', 'attended', 'failed', 'certified']`
- Inconsistent attendance tracking across tables

### Missing Foreign Key Relationships:
- `session_roster.user_id` has no foreign key constraint to `users(id)`
- `session_roster.certificate_id` has no foreign key to `certificates(id)`
- Circular dependency warning in users/organizations schema

## 4. **Production Risk Errors**

### 400/500 Error Causes:
1. **Foreign Key Violations**: Deleting users/sessions without cascade deletes
2. **Missing Required Fields**: Creating sessions without `max_participants` or `delivery_mode`
3. **Check Constraint Violations**: Invalid status/role values
4. **Unique Constraint Violations**: Duplicate `training_standards.code`
5. **Invalid Date Formats**: Manual date conversions without validation

### Performance Issues:
- No pagination in dashboard data fetching
- Multiple count queries could be optimized
- Missing indexes not shown but likely needed
